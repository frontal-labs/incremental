Incremental is a high-performance **incremental computation engine** for building dependency-driven systems. It records what each task reads, lists, probes, and writes, stores those observations as content-hashed records, and answers one question:

> Given the changes since the last known-good baseline, which tasks are invalid — and why?

The engine is written in **Goose** (`core/`). Protocol clients are **TypeScript** (`bindings/node`), **Python** (`bindings/python`), and there is a Rust binding (`bindings/rust`). The specification lives in `spec/`, and the conformance suite (41 cases) is in `conformance/`.

## What it solves

In large repositories, running every test, build, or type-check on every change wastes time and money. Incremental avoids re-running work that cannot be affected by a change. It records **observations** of what each task actually touched, then, given a `ChangeSet`, computes exactly which tasks must re-run and which can be safely skipped — never skipping silently.

## Core principles

- **Soundness first.** A task may only be skipped if it has a **certificate**: an observation at the current baseline whose inputs are all unchanged. No silent skips.
- **Protocol-first.** All access goes through **Incremental Protocol v1** over JSON Lines on stdio. Bindings are thin clients; the engine is language-neutral.
- **Append-only log as source of truth.** Store state lives in `<store>/tg.log` (JSON Lines). Indexes are disposable caches, replayed from the log.
- **Deterministic.** Plans are deterministic regardless of input order; all lists are sorted.
- **Generic engine.** Core knows nothing about Vitest, git, or tests — those are adapters.

## High-level architecture

```text
Consumers (CI, MCP agents, humans)
    ↓
Adapters (Vitest, git, strace oracle, MCP server)
    ↓
Incremental Protocol v1 (JSON Lines over stdio / unix socket)
    ↓
Engine Core (store, index, policy, plan generation, verification)
```

Key components:

| Component | Responsibility |
|-----------|----------------|
| **Core** | Append-only log, store, index, policy (`plan`), plan generation, protocol server, verification |
| **CLI** | Thin binding over protocol (`incremental` binary, built from `core/src/main.goose`) |
| **Bindings** | Node client (`@incremental/client`), Python, Rust |
| **Adapters** | Recorders and drivers for Vitest, git (change sets), strace (oracle), MCP server |
| **Conformance** | Language-neutral test suite ensuring byte-identical behavior across bindings |

## Current state

- Protocol v1 and schemas are in `spec/`. Conformance cases C01-C41 are in `conformance/cases/`; Vitest adapter cases V01-V16 are in `adapters/vitest/fixtures/cases/`.
- Core is built in Goose under `core/src/`: `store.goose`, `policy.goose`, `protocol.goose`, `main.goose`. All 41 conformance cases pass.
- Bindings: the Node client and the Python binding are done. The Rust binding has no status record yet.
- Adapters are built under `adapters/`.
- Milestone status, including open decisions, is in `STATUS.md` (generated by `make status`) and `DECISIONS.md`.
