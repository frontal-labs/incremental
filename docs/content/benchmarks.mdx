Full tables, methodology, and known issues are in [`BENCHMARKS.md`](../BENCHMARKS.md). Measured on macOS (arm64), 2026-11-05.

## The number that matters

**Per-invocation cost, not per-query cost.** A single `incremental-vitest run` pays about **2.5 s** of fixed overhead even when nothing changed (Node start, imports, spawning the engine, loading the store, git change-set queries), and each selected test file then costs about **1 s** of Vitest cold start (one process per file, run in parallel). A plan-and-report `--shadow` run is about **0.5 s**. The engine's own warm `affected` query is about **0.1 ms** — the engine is not the bottleneck; the overhead and per-file runner cost are what you actually feel.

## Replay accuracy

(`make bench-replay`, 10 commits per fixture): **zero false skips** across the default fixture and the Nx, Turborepo, and Bazel monorepo fixtures. The sample is small: ten commits give a rule-of-three upper bound of 30%, so this shows no false skip was found — not that the rate is low.

## Warm query latency

(`benchmarks/warm-plan.mjs`, 1,000 queries × 3 iterations, each query invalidates exactly one task):

| Tasks | Per-query p50 | Per-query p99 | Process load (median) |
|-------|---------------|---------------|-----------------------|
| 10,000 | 0.100 ms | 0.650 ms | 38 ms |
| 100,000 | 0.093 ms | 0.661 ms | 394 ms (before the index fix) |

The warm query target (p50 under 5 ms and p99 under 20 ms at 100k tasks) is **met**.

The cold CLI target (under 300 ms at 100k tasks) is **not yet confirmed**. Loading 100k observations took about 394 ms before the index-load fix. After it, a cold `stats` on the same store took 99 ms wall (hyperfine median, 30 runs) at machine load about 55. That figure is not final: re-measure on an idle machine before quoting it.

## Comparison with other tools

(`node scripts/bench-compare.mjs 10`): affected-detection on the 4-package monorepo fixtures, median of 10 runs:

| Tool | Median |
|------|--------|
| Nx | 897 ms |
| Turbo | 151 ms |
| Bazel | 1,147 ms |

These are cold CLI runs on small fixtures. Incremental's warm query is not the same operation, so do not read a ratio between these rows as a speedup.

Reproduce with `make bench` (after `make build`). Raw outputs are written to `benchmarks/results/`.

## Known issues

- Cold CLI target under 300 ms at 100k tasks not yet confirmed
- Replay sample is small (10 commits); upper bound on false-skip rate is 30%
- `test-oracle` (strace) is Linux-only, skipped on macOS
- `compact` not yet implemented

## Run the benchmarks

```sh
make build
make bench        # writes raw outputs to benchmarks/results/
make bench-replay # replay accuracy across fixtures
make bench-smoke  # smoke test
```
