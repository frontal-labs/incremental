## Ground Rules

1. Milestone done only when verify passes, output saved to `evidence/<id>.txt`, committed as `<id>: <deliverable>`
2. **Specification before implementation** - Conformance cases and schemas committed first. Core/Bindings must NOT edit `spec/` or `conformance/cases/` - use change requests
3. Never weaken tests, change benchmark targets, or edit gates after seeing results
4. Never skip silently - unknown/unverifiable input means invalid
5. Never claim success without running command and reading output
6. Log surprises in `FRICTION.md`, choices in `DECISIONS.md`, versions in `VERSIONS.md` (append-only)
7. Edit only paths your role owns
8. Core must stay under 8000 lines excluding tests/generated code (`make loc`)
9. Dependencies restricted per rules (Core minimal, Bindings stdlib+protocol, etc.)
10. No credentials/paid services, no installs outside repo except toolchain
11. Pin every version in `VERSIONS.md` with exact version; pin must be >=14 days old unless DECISIONS explains exception
12. Every `make` target prints `PASS <target>` or `FAIL <target>` and exits 0/nonzero
13. Units: ms for time, bytes for sizes, repo-relative paths with `/`, hashes `sha256:<hex>`, RFC3339 UTC timestamps, UTF-8 identifiers

## Workflow

1. Read sections 0,1,2,14 + your role's milestones in section 15
2. Check `STATUS.md` and `spec/CHANGE_REQUESTS.md`
3. Work only on first milestone in your role's list that's `todo`/`doing` with deps done. Set to `doing` in status file
4. When finished: run verify command, save output to `evidence/<id>.txt`, commit as `<id>: <deliverable>`, set state to `verify`, stop
5. Spec/Conformance does fresh clone and verifies → writes signoff, sets to `done`

## Branches & Commits

- Branch: `agent/<role>/<milestone>`
- Commit: `<id>: <deliverable>`
- Conformance cases/schemas committed in E1 before any code

## Status

- Role status in `status/<ROLE>.json`: `{"id":"E2","state":"doing","evidence":"evidence/E2.txt","notes":""}`
- States: `todo`, `doing`, `verify`, `done`, `blocked`, `skipped`
- `STATUS.md` generated by `make status` (don't edit by hand)

## Change Requests

Append to `spec/CHANGE_REQUESTS.md`:

```
## CR-004 <title>
- Requester: <role>
- Milestone affected: <id>
- What: <exact change to section N>
- Why: <evidence/output>
- Impact: <files/cases/schemas>
- Status: open | accepted | rejected  (Spec/Conformance sets, bumps spec version)
```

## Stop Conditions (escalate to human)

- Required recorder capability can't be observed after 2 approaches
- Existing tool provides all of: runtime-recorded deps for Vitest, stable protocol, sound skips with reason codes
- <50 evaluated commits for replay
- Spec ambiguity changing protocol/log/plan shape (write CR if small, stop if changes shape)
- Core exceeds 8000 lines
- Needs credentials/paid services/software outside repo/Linux container runtime fails
- Two milestones in a row fail sign-off
- Check fails due to non-code issue (e.g., conformance case wrong) - report, don't edit case
